= Quarkus IPFS

Quarkus IPFS embeds a Peergos Nabu node in a Quarkus application.
Use CDI to store blocks and retrieve them by CID.
The extension also provides peer, DAG, and IPNS operations.

== Installation and CDI

Use Java 21 or newer and the Quarkus 4.0.0 BOM.
Use the Maven coordinates `io.github.pedropietro:quarkus-ipfs` with a published version. https://central.sonatype.com/artifact/io.github.pedropietro/quarkus-ipfs[Quarkus IPFS on Maven Central]
Configure JitPack in the consumer if its repository policy requires it.
The README includes a complete REST resource that injects `BlockService`, writes a block, and reads it by CID. https://github.com/pedropietro/quarkus-ipfs#quick-start[Installation and CDI example]

== UnixFS files and directories

Use `DagService` to add files, read a file by its root CID, and create or list named directory entries.
New UnixFS directories have a deterministic link order.
The extension writes 256 KiB raw leaves and limits each newly imported file node to 174 ordered links. Larger imports use nested file nodes.
Files within the limit keep the previous encoding. Re-importing larger files can yield a different root CID, and existing flat roots remain readable.
The extension reads raw files and DAG-PB UnixFS files, including inline data and nested file nodes.
`getFile(cid)` returns a byte array containing the complete file.
Use `writeFile(cid, output)` to write the file to an `OutputStream` in block order and obtain the byte count from the returned future.
Keep the stream open until the future completes and close or flush it in the caller.
If reading or writing fails, the destination may already contain part of the file.
With FILE storage, the application can read files larger than the heap without retaining the whole payload in memory.
Keep the blocks for existing CIDs. The extension recognizes the multiblock file layout produced by versions through 0.2.0 and reads the names in directories written by those versions.
The legacy file format remains readable by Quarkus IPFS. For a standard UnixFS file CID, import the file again and use the new CID.

== IPNS names

Inject `IpnsService` to publish a signed value under the local peer ID and resolve values published by peers.
Call `publish(value, sequence, hoursTtl)` with a path such as `/ipfs/<CID>` and increase the sequence each time the value changes.
The record expires after the given number of hours. Use `getLocalIpnsName()` to obtain the base58 peer ID.

Call `resolve(peerId, minResults)` with the publisher's base58 peer ID.
The lookup finishes the current batch of peer queries after reaching the requested number of valid records.
It returns the highest sequence among the records found, using the later expiration time to break a tie.
The future fails when the lookup times out or finds no valid records.
The node accepts V2-only records and checks any legacy Protobuf fields against the signed DAG-CBOR values.
Configure `quarkus.ipfs.bootstrap-addresses` to join the DHT and share records with other peers.

== Micrometer metrics

Add `io.quarkus:quarkus-micrometer` to the application to register IPFS meters with Micrometer.
For Prometheus, use `io.quarkus:quarkus-micrometer-registry-prometheus` and scrape `/q/metrics`.
Set `quarkus.ipfs.metrics-enabled=false` at build time to turn off IPFS meters while keeping the Micrometer registry.

[cols="1,1,3",options="header"]
|===
|Meter |Type |Measurement
|`ipfs.peers.connected` |Gauge |Distinct peers currently connected to the embedded node.
|`ipfs.operations` |Counter |Completed `block_read`, `block_write`, `ipns_publish`, and `ipns_resolve` calls, tagged with the `operation` and the `outcome` (`success` or `failure`).
|`ipfs.kubo.operation.duration` |Timer |Count and total duration of completed Kubo client calls, including cancellations.
|===

Block counters cover `BlockService.get` and `put`. A block read counts once, including when it fetches the block from another peer.
IPNS counters cover `IpnsService.publish` and `resolve`. A publication that succeeds locally with zero DHT acknowledgements counts as a success.
Prometheus exposes these embedded-node meters as `ipfs_peers_connected` and `ipfs_operations_total`.

The Kubo timer is also available when the embedded node is disabled.
Its `operation` tag is `block_get`, `cat`, or `add`.
Its `outcome` tag is `success`, `http_error`, `timeout`, `cancelled`, `stream_error` (late `X-Stream-Error` trailer), or `failure` (for example, a TLS or local I/O error).
Prometheus exposes the count and cumulative duration as `ipfs_kubo_operation_duration_seconds_count` and `ipfs_kubo_operation_duration_seconds_sum`.

== Read blocks and transfer UnixFS files through an external Kubo node

Enable `quarkus.ipfs.kubo.enabled=true` at build time to inject the optional CDI bean `io.quarkiverse.ipfs.runtime.KuboClient`.
The client works alongside the embedded node. Set `quarkus.ipfs.enabled=false` at build time to run with the Kubo client only.

[source,properties]
----
quarkus.ipfs.kubo.enabled=true
quarkus.ipfs.kubo.api-url=http://127.0.0.1:5001
quarkus.ipfs.kubo.timeout=30s
----

Supply `quarkus.ipfs.kubo.bearer-token` through a secret-backed configuration source when Kubo requires bearer authentication.

For a Kubo API behind an HTTPS reverse proxy with a private CA, select a named Quarkus TLS trust store.
The proxy can mount the RPC under a path prefix.

[source,properties]
----
quarkus.ipfs.kubo.api-url=https://kubo.example.com/ipfs-rpc
quarkus.ipfs.kubo.tls-configuration-name=kubo
quarkus.tls.kubo.trust-store.pem.certs=/etc/certs/kubo-ca.pem
----

The trust store applies to block reads and file transfers. The client verifies the proxy hostname and does not follow redirects.
Configure the proxy to forward HTTP trailers so the client receives errors such as `X-Stream-Error`.
The client loads the configured trust store at initialization and listens for updates to the named configuration.
Set `quarkus.tls.kubo.reload-period` to enable periodic reloads, or reload the configuration and fire a `CertificateUpdatedEvent` from the application.
New requests use the updated trust store and connections already serving a request can finish.
When replacing a CA, distribute a trust store with both roots before switching the proxy certificate, then remove the old root.
Use HTTPS for a remote RPC server that carries credentials.
The base URL may include a reverse-proxy prefix.

Call `KuboClient.getBlock(cid)` to fetch raw bytes asynchronously. Invalid CIDs fail with `IllegalArgumentException`, missing blocks with `NoSuchElementException`, and other HTTP errors with `KuboRequestException`. A request that reaches its time limit fails with `TimeoutException`.

Call `KuboClient.writeFile(cid, output)` to stream a UnixFS file and obtain the byte count.
The caller manages flushing and closing the destination.
On cancellation or timeout, the client releases the HTTP response and interrupts the transfer.
An in-progress write can finish later if the destination ignores interruption. The destination can contain partial data after a failure.

Call `KuboClient.addFile(input, pin)` to import one UnixFS file with the Kubo add RPC and return its root CID.
The caller closes the input stream. Set `pin` to choose whether Kubo retains the imported file during garbage collection.
The timeout covers the request body and response. Cancellation or timeout can leave data on the Kubo node.
Both file operations check for an `X-Stream-Error` trailer before reporting success. A late server error fails the future even after the client receives the CID or writes every advertised byte.
Grant the configured bearer token access to `/api/v0/add` for uploads.

Call `KuboClient.listDirectory(cid)` for an immutable list of direct UnixFS directory entries, each with a name and CID in Kubo's order.
To list a nested directory, pass the CID of its entry to the same method.
Grant the token access to `/api/v0/files/stat` and `/api/v0/ls`.
The client rejects file CIDs and listing responses larger than 1 MiB.

With SmallRye Health installed, set `quarkus.ipfs.kubo.health-enabled=true` at build time to add a `kubo` check to `/q/health/ready`.
The check works when the embedded node is disabled and uses the client's TLS configuration and bearer token.
Grant the token access to `/api/v0/version`. The probe uses the shorter of the Kubo timeout and two seconds.
The check reports DOWN when the RPC returns an unsuccessful response or cannot be reached, and reports UP again on the next successful probe.

== Storage and identity

The default storage backend, `RAM`, keeps blocks in memory for one application run.
Set `FILE` to preserve blocks across application restarts.
The extension creates the block directory under the configured path if needed.
Choose a dedicated, writable directory and reuse it on restart.

[source,properties]
----
quarkus.ipfs.storage-type=FILE
quarkus.ipfs.storage-path=./var/ipfs
----

The storage backend is fixed at build time.
The path can be set at runtime.
The node normally generates a new peer identity on startup.
To keep the same identity across restarts, supply `quarkus.ipfs.identity-private-key` through a secret-backed configuration source.

== Development and tests

Dev Services starts the embedded node in dev and test mode with no Docker requirement.
The default swarm listener uses loopback and an ephemeral TCP port.
Set `quarkus.ipfs.devservices.port` for a fixed port when both the global and IPFS Dev Services flags are enabled.
Explicit `quarkus.ipfs.swarm-addresses` takes precedence.
Disabling Dev Services selects the regular node defaults.
Set `quarkus.ipfs.enabled=false` to disable the node and its CDI services.

Each live reload starts a fresh node and closes the previous one.
RAM blocks and generated peer identities are recreated on reload.
The `quarkus.ipfs.devservices.shared` setting is deprecated.

== Network and readiness

Configure `quarkus.ipfs.swarm-addresses` to listen on a deliberate interface and `quarkus.ipfs.bootstrap-addresses` to contact known peers on startup.
The default bootstrap list is empty.
Nabu can still discover local peers using mDNS.
TCP is the default transport.
QUIC addresses require the matching platform classifier of `io.netty:netty-codec-native-quic`.

Block reads try the local store first.
Bitswap can fetch missing blocks from connected peers or providers discovered via the DHT.
Use `quarkus.ipfs.run-bitswap=false` for local reads only.
Enable `quarkus.ipfs.provide-blocks` if you want to announce blocks to the DHT.

With SmallRye Health installed and `quarkus.ipfs.health-enabled=true`, `/q/health/ready` includes the IPFS check.
The check reports the status of the local node.

See the xref:config-reference.adoc[configuration reference] for all properties.
